# 揭榜适配-唐浩扬-视障友好适配

> 课程项目：校园失物招领系统（`campus-lost-and-found`，Spring Boot + Vue 3）
> 适配性质：仅做无障碍适配，**未新增任何业务功能**，接口、数据库、页面流程均未改变
> 验证环境：Windows 11 · Microsoft Edge 158（强制颜色模式 / 键盘）· Chrome DevTools Protocol 无障碍树 · Node 24

## 一、平台说明：为什么按 Web 无障碍规范做

本项目是 B/S 结构（Vue 3 + Element Plus 前端），不是 Windows 桌面程序，也不是 Android 应用。任务书给出的两条路径是「Windows 桌面」与「Android 移动」，本项目最贴近的是**在 Windows 上用屏幕阅读器访问的 Web 应用**，所以按 Web 端无障碍标准实施，并在 Windows 上验证：

| 任务书要求 | 本项目对应做法 | 依据 |
|---|---|---|
| ① 交互控件有正确的无障碍**名称、角色、状态** | ARIA 名称/角色/状态 + 表单必填状态 | WAI-ARIA 1.2、WCAG 2.2 SC 4.1.2 |
| ② 全键盘可操作、**焦点顺序合理可感知** | 跳过导航、焦点可见、换页焦点落点、`aria-current` | WCAG 2.2 SC 2.1.1 / 2.4.3 / 2.4.7 |
| ③ 支持系统**高对比度** | `@media (forced-colors: active)` 补边框与下划线 | WCAG 2.2 SC 1.4.11、Windows 高对比度主题 |
| ④ 原有功能**可用、完整、不中断** | 29 项既有单测 + 新增 6 项语义断言全部通过 | 回归验证 |

> 说明：Windows 上的屏幕阅读器（NVDA / 讲述人）通过 Edge 读取的正是浏览器无障碍树，与系统级控件走同一套 UIA 通道，所以「Web 端 ARIA 适配 + Windows 屏幕阅读器验证」是同一件事的两端，不是替代品。

### 2. 键盘操作与焦点

- **跳过导航**（`App.vue` + `base.css`）：全站第一个可聚焦元素是「跳到主内容」，指向 `#main-content`，按回车把焦点交给 `<main tabindex="-1">`。键盘用户不必每页 Tab 过 4~5 个导航链接。
- **焦点可见统一**（`base.css`）：`:focus-visible` 统一 2px 蓝色描边 + 2px 偏移；程序性聚焦主内容时不画框。
- **换页后焦点归位**（`router/index.ts` + `utils/a11y.ts`）：`afterEach` 里改标题 → 播报「XX页面已加载」→ `requestAnimationFrame` 后把焦点移到主内容区，读屏从 `h1` 开始读。
- **路由标题**（`router/index.ts`）：`document.title` 由固定「校园失物招领」变为「浏览物品 · 校园失物招领」，浏览器标签与读屏标题同步。
- **弹窗关闭后焦点归还**（`MyItemsView.vue`）：下架确认框关闭时，Element Plus 会把焦点丢给 `body`；实测发现后补了“记录触发按钮 → 关闭后 `focus()` 回去”，物品已下架、按钮不存在时则把焦点交给主内容区。

### 3. 高对比度（强制颜色）

`base.css` 新增 `@media (forced-colors: active)`：卡片、输入框、下拉框、文本域、标签、按钮、分页改为 `1px solid ButtonText` 边框；链接加下划线；当前导航项加 `Highlight` 描边；表格补 `CanvasText` 边框。

改前实测：输入框、下拉框、卡片在强制颜色下**边框完全消失**，只能靠文字位置猜控件边界；改后控件轮廓、当前页、可点击链接全部可辨（见证据图 02 / 03）。

### 4. 功能完整性

未改任何接口调用、数据流、路由表结构；`el-form` 仅隐藏了 Element Plus 自带的星号文本并改用 `aria-hidden` 星号，表单校验规则、提交流程、幂等键逻辑均未触碰。

## 三、怎么验证的（可复现）

### 工具

| 目的 | 工具 |
|---|---|
| 读出“屏幕阅读器实际听到什么” | Edge + CDP `Accessibility.getFullAXTree`（导出完整无障碍树文本） |
| 复现视障用户键盘路径 | CDP `Input.dispatchKeyEvent` 模拟 Tab / Enter，逐条记录焦点元素与焦点框样式 |
| 高对比度 | CDP `Emulation.setEmulatedMedia` 打开 `forced-colors: active` 截图 |
| 回归 | `npx vue-tsc --build`、`npx vitest run` |

驱动脚本见 `docs/a11y-evidence/cdp.mjs`，用法：`node cdp.mjs <标签> all`（全量采集）、`node cdp.mjs <标签> skip`（跳过导航验证）、`node cdp.mjs <标签> detail <物品ID>`。

### 实测结果

1. **键盘第一步**：改前第 1 个 Tab 停在 logo 链接「校园失物招领」；改后第 1 个 Tab 停在「跳到主内容」（2px 描边可见），回车后焦点落在 `MAIN#main-content`，页面 `h1` 为“浏览物品”。
2. **控件名称**：`textbox "账号"` 与 `textbox "密码"` 不再带星号；`required=true` 正确暴露（改前 `required=false`）。
3. **导航地标**：`navigation "主导航"` 出现在无障碍树中；当前页链接带 `aria-current="page"`。
4. **结果播报区**：无障碍树中出现 `status {live=polite atomic=true}`，内容“第 1 页，共 1 条物品，本页 1 条”。
5. **页面标题**：10 个页面逐一核对，标题分别为「首页 / 浏览物品 / 物品详情 / 发布物品信息 / 我的发布 / 个人资料 / 登录 / 注册 / 管理后台 / 页面不存在 · 校园失物招领」。
6. **高对比度**：改前 3 类控件无边框，改后全部有 `ButtonText` 边框、链接带下划线。
7. **回归**：`vue-tsc --build` 通过；`vitest run` **8 个文件 35 项测试全部通过**（原 29 项 + 新增 6 项语义断言）。

### 新增的自动化断言（`src/__tests__/a11y.spec.ts`）

- 应用第一个可聚焦元素是「跳到主内容」，且 `#main-content` 落点真实存在；
- 路由播报区具备 `role="status"` + `aria-live="polite"`，且初始为空；
- 播报内容“先清空再写入”，保证同一句重复出现也会被再次朗读；
- `focusMainContent()` 确实把焦点交给 `#main-content`，无主内容区时静默返回；
- 主内容区为 `<main tabindex="-1">`，可被程序聚焦。

这几条断言把“无障碍结构”变成会失败的测试，后续改版一旦把跳过导航或播报区删掉，CI 直接红。

### 全键盘端到端走查（新增，脚本 `docs/a11y-evidence/e2e.mjs`）

全程只发送 `Tab` / `Enter` / `Esc` / 方向键和文字输入，**不发送任何鼠标事件**，完整跑通一条业务链路：

| 步骤 | 键盘操作 | 实测结果 |
|---|---|---|
| 1 登录 | Tab 到账号（8 次）→ 输入 → Tab 到密码 → 输入 → Tab 到登录 → Enter | 跳转 `/`，导航出现「我的发布」 |
| 2 进发布页 | Tab 5 次到导航「发布信息」→ Enter | 进入 `/items/new`，h1「发布物品信息」 |
| 3 填表提交 | Tab 到标题/地点/日期/描述 → 逐项输入 → Tab 到「提交审核」→ Enter | 日期 2026-11-20 填好，出现「已提交」提示 |
| 4 下架 | Tab 11 次到「下架」→ Enter → 弹窗 → Esc → 再 Enter 确认 | 弹窗 `dialog "下架信息"`，初始焦点在「确定下架」，Esc 后焦点回到「下架」按钮，确认后转为已下架 |

这一步同时验证了任务书第 4 条「原有功能在无障碍模式下可用、完整、不中断」，并**顺带发现并修复了一个真实缺陷**：弹窗关闭后焦点原本会掉到 `body`，键盘用户要从头 Tab 一遍；现在焦点会回到触发按钮。

### 演示辅助：页面朗读按钮（`ReadAloudButton.vue`，录制视频用）

为了录一段“听得见”的证据，加了一个朗读按钮：点一下（或按 `Alt+R`）从页面标题开始逐段朗读，正在读的段落会高亮，读到的位置自动滚到视野中间，`Esc` 或再按一次停止。

- 实现：Web Speech API（`speechSynthesis`，`lang=zh-CN`），按“标题 → h1 → 说明文字 → 表单标签 → 按钮 → 列表项”顺序切块，`onend` 逐段推进。
- **边界：这是页面自朗读，不是屏幕阅读器**。屏幕阅读器（NVDA/讲述人）读的是浏览器无障碍树，两者不是一回事，材料里分开写，不拿它冒充屏幕阅读器。
- **不进入提交构建**：只在 `npm run dev` 或地址带 `?read=1` 时挂载，`npm run build` 的产物里没有这段代码，所以不构成“新增业务功能”。
- 验证：用假 `speechSynthesis` 记录它会念什么，按钮回车触发和 `Alt+R` 触发都产生 13 段（1 段开场 + 12 段正文），内容见 `09_朗读按钮_朗读内容清单.txt`。

## 五、还没做的（如实说明）

- **原生 `<input type="date">`** 在 Edge 无障碍树里被拆成“年/月/日”三个数值输入框，且名称重复（`"年 年"`）。这是 Chromium 内置控件行为，页面无法改写；键盘可以正常填写（逐段输入 + 方向键切换，见走查日志步骤 3），已在说明中标注。
- **未做真实 NVDA 录屏**：本机没有安装 NVDA（只有系统「讲述人」），本文证据以 Edge 无障碍树、键盘路径、强制颜色截图为主。浏览器无障碍树正是 NVDA/讲述人读取的数据源；若课程要求录屏，补一段讲述人朗读视频即可，不需要改代码。

```powershell
cd backend; .\mvnw.cmd spring-boot:run
cd frontend; npm run dev

# 2. 采集无障碍树 / 键盘路径 / 截图（Edge 无头 + CDP）
node docs/a11y-evidence/cdp.mjs after all
node docs/a11y-evidence/cdp.mjs after skip
node docs/a11y-evidence/e2e.mjs        # 全键盘端到端走查

# 3. 回归
cd frontend; npx vue-tsc --build; npx vitest run
```
