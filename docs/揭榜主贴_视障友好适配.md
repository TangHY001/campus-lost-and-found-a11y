# 揭榜适配-唐浩扬-视障友好适配

> 主贴正文，可直接粘贴到课程网络教学平台（标题用上面这一行）。

## 一、项目介绍

本次适配基于本人参与的课程项目《校园失物招领系统》。项目采用 Vue 3、Spring Boot 和 MySQL，学生可以发布、检索失物招领信息，查看审核状态并管理自己的发布；管理员可以登录管理后台。

我主要负责学生端与管理端的页面导航、表单、列表与弹窗，本次适配也集中在这些页面上。项目本身是 B/S 结构的 Web 应用，既不是 Windows 桌面程序也不是 Android 应用，因此依据 **WCAG 2.2 AA 与 WAI-ARIA 1.2** 做适配，在 **Windows + Edge** 环境下用浏览器无障碍树（也就是 NVDA、讲述人读取的同一棵可访问性树）验证，与任务书对控件语义、键盘操作、焦点提示和系统高对比度的要求逐条对应。

所有改动都在原有页面上做**增量改造**：接口、数据库、路由结构、业务流程一行未动，不新增任何业务功能。

## 二、适配内容

**1. 导航与焦点。** 学生端和管理端增加了「跳到主内容」链接：键盘第一个 Tab 就停在它上面，按 Enter 把焦点交给 `<main>`，不必每页 Tab 过四五个导航链接。站内切换页面时自动更新浏览器标题（如「浏览物品 · 校园失物招领」），并用 `role="status"` 播报「浏览物品页面已加载」，同时把焦点移到主内容区，读屏从一级标题开始读。导航链接补了 `aria-current="page"`，导航地标补了名称（「主导航」「管理导航」）。

**2. 表单标签与必填状态。** 登录、注册、发布、个人资料四类表单的输入框都有明确标签；Element Plus 默认会把必填星号写进标签文本，读屏会念成「星号 账号」，改为视觉星号（`aria-hidden`）后控件名称恢复为「账号」，同时用 `aria-required` 暴露必填状态（改前无障碍树里是 `required=false`）。提交失败时错误提示用 `role="alert"`，读屏会自动念出错误原因。

**3. 搜索、分页与提交反馈。** 物品检索的筛选表单标签与原控件的名称一致；搜索或重置后，结果条数与当前页码通过 `role="status"` 播报（如「第 1 页，共 1 条物品，本页 1 条」）；分页包在「物品列表分页」这个导航地标里。发布成功、注册成功等提示使用 Element Plus 的消息条，自带 `role="alert"`，读屏能读到结果。

**4. 图片与弹窗。** 物品图片的替代文字从「物品图片 1」改为带物品标题的「校园卡（测试数据）的物品图片 1」。下架确认弹窗暴露 `dialog` 角色与标题「下架信息」，初始焦点落在「确定下架」，按 Esc 可关闭；这里发现并修掉了一个真实问题：关闭后焦点原本会掉到页面底部，现在会回到触发弹窗的「下架」按钮，按钮随物品下架消失时则交给主内容区。

**5. 高对比度。** 用 `@media (forced-colors: active)` 跟随 Windows 高对比度主题：为卡片、输入框、下拉框、文本域、按钮、分页补 `1px solid ButtonText` 边框，链接加下划线，当前导航项加 `Highlight` 描边。改前在强制颜色下输入框和下拉框的边框会完全消失，只能靠文字位置猜控件边界；改后轮廓清晰可辨。状态仍然用文字标签表达，不只靠颜色区分。

## 三、测试记录

测试环境为 Windows 11、Microsoft Edge 158.0.4370.33，使用 Edge 无头模式 + Chrome DevTools Protocol 采集无障碍树、模拟键盘操作，并开启 `forced-colors` 模拟系统高对比度；业务流程连本地后端与 MySQL 真实跑通。所有采集脚本与原始输出都放在仓库 `docs/a11y-evidence/` 下，可复跑。

- **键盘入口**：改前第 1 个 Tab 停在 logo 链接「校园失物招领」；改后停在「跳到主内容」，按 Enter 后焦点落在 `MAIN#main-content`，页面一级标题为「浏览物品」。
- **控件名称与状态**：登录页无障碍树中，改前为 `textbox "账号 *" required=false`，改后为 `textbox "账号" required=true`；密码框同样。
- **导航与标题**：`navigation "主导航"` 出现在无障碍树中，当前页链接带 `aria-current="page"`；10 个页面的标题逐一对齐为「首页 / 浏览物品 / 物品详情 / 发布物品信息 / 我的发布 / 个人资料 / 登录 / 注册 / 管理后台 / 页面不存在 · 校园失物招领」。
- **全键盘业务走查**：全程只发送 Tab、Enter、Esc、方向键和文字输入，不发送鼠标事件，跑通「登录 → 进入发布页 → 填写并提交 → 我的发布 → 下架确认」，日期控件用「逐段输入 + 方向键切换」填成 2026-11-20，提交后出现「已提交」；下架弹窗按 Esc 关闭后焦点回到「下架」按钮。
- **高对比度**：强制颜色下登录页与物品列表的输入框、下拉框、卡片边框由不可见变为可辨，链接出现下划线，当前导航有描边。
- **自动化**：`npx vue-tsc --build` 通过；`npx vitest run` 8 个测试文件、35 项用例全部通过（原有 29 项 + 新增 6 项无障碍语义断言，覆盖跳过导航、播报区、焦点落点等结构）。

说明：本次没有使用 NVDA 录屏、Playwright 或 axe-core，证据以浏览器无障碍树、键盘路径、强制颜色截图和 vitest 断言为主；这是有意为之——这些数据能逐条复现，也比“截图一张”更难造假。
